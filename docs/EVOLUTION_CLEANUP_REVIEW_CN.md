# Evolution 实现精简与代码复查

2026-09-11。范围覆盖 Evolution 的配置、历史分析、规则筛选、多仓调度、审批、执行验证、知识沉淀及统一 MCP 接口。
本次处理实际重复工作和无效入口；外部模型质量、业务适配器和真实设备收益仍需业务环境验收。

## 已处理的问题

| 问题 | 处理 | 实际效果 |
|---|---|---|
| `.env` 和 workspace 示例重复配置目录、模型及预算 | 复用原平台 YAML、原环境和 OpenCode 配置，代码补齐默认值 | 最小示例只保留项目范围、依赖和责任人 |
| 配置规则位于 API 层，CLI/setup 又反向导入 API | 配置加载、归一化和校验统一到 `evolution/configuration.py` | API 负责 MCP 注册；旧 Python 导入位置保留薄导出 |
| 读取 YAML 时，`core` 包同时预加载 LLM 和运行上下文 | 沿用项目已有的按需导出模式，实际使用时才加载对应模块 | 本地 schema、配置和资料命令无需加载模型、存储与运行时；原导入名称和类型身份保持兼容 |
| 三个 setup 分支重复拼接同一 MCP 连接结构 | 共用一个片段生成函数 | 共享 YAML 与旧 JSON 使用同一连接格式 |
| 旧 `distill_patterns` 无业务调用、只返回空列表 | 删除空实现及出口，测试真实历史入库与待分析状态 | 历史分析统一走 `change_analysis` 和 Worker/Skill，不再留下名为“蒸馏”的空入口 |
| 普通扫描和分页扫描各自实现 pattern 最新版本/退役规则 | 共用 `active_pattern_records` | 同样拒绝退役后回退到旧 active 版本；新版本须明确策展激活 |
| 分页扫描已有冻结配置仍读当前全库 overlay，并开启空事务 | 有快照时直接使用快照，仅在没有快照时查询 | 减少无效 SQL 和锁竞争，保留固定输入语义 |
| 状态、列表和证据读取也使用 `BEGIN IMMEDIATE` | 增加数据库强制只读的快照事务 | 读者能读取已提交状态，不等待未提交写者；审批和占用仍使用原子写事务 |
| 列表先取 ID 再逐条查询 | 一次查询读取整页必要列 | 100 条列表从 101 次 SELECT 降为 1 次 |
| 每个项目分别重复聚合整轮历史状态 | 同一只读快照中按项目聚合一次 | 减少重复扫描，并使 run、manifest、计数和扫描状态一致 |
| 历史关联、任务关联和审计查找缺少对应索引 | 增加限定记录类型的关联索引和实体审计索引 | 避免为每个 source/项目重复全表检索；旧库自动创建索引，不重写记录 |
| supervisor 在推进 run 后又推进同一扫描 | 在独立扫描分页前排除本轮已处理扫描 | 每轮推进一次，并让独立扫描获得调度机会 |
| 重复保存同一模型响应、重复读取档案 pattern、无用参数及二次过滤 | 删除冗余操作和三个未使用参数 | 保留原证据摘要、审批 ID、候选版本及结果契约 |

## 复查重点

- 多仓边界：显式选仓、独立依赖清单、固定 Git revision、稳定项目身份及跨目录拒绝规则。
- 历史分析：提交标题不产生 pattern；实际 before/after 代码引用、上下文预算和未知条件保持可见。
- 规则筛选：普通/分页扫描共用版本规则；过滤结果不替代语义适用性复核。
- 审批：责任目录、签名、时效、证据摘要、候选版本和重复请求检查继续生效。
- 执行：方案与代码独立评审、隔离 worktree、执行占用、迟到结果隔离和幂等重放继续生效。
- 验证：双侧版本、依赖版本清单、测试环境、原始报告、正确性和 A/B 策略必须一致。
- 沉淀：模拟结果不升级为生产验证；共享 Hub 晋升仍经过独立策展。
- 兼容：旧 JSON、已有环境覆盖及旧 MCP 导入是有调用的适配入口，内部复用同一实现。
- 契约：各类 Pydantic 模型的严格程度、引文空白保留、事务内二次检查有不同用途，不按表面相似合并。
