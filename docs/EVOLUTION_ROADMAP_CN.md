## 1. 先准确界定当前实现

当前 `hmopt.evolution` 已提供本地持久对象、不可变 Git 读取、字面模式筛选、责任人确认、提交与评审绑定、配对 A/B 判定、知识记录和分层晋升。它不启动 LLM、编辑目标仓库、操作设备或向团队自动安装技能。

| 当前机制 | 实际限制 | 对持续运行的影响 |
|---|---|---|
| Git 增量采集 | 第一父链按从旧到新分页；合并以第一父提交差异代表；仓库身份及游标与本地路径关联 | 不是完整评审/DAG 采集；仓库迁移、多分支与强制改写需要新的身份及恢复契约 |
| 有界挖掘和扫描 | Git 操作有总时限与命令时限；历史、树列表、文件和总 blob 字节均有上限 | “本页处理完成”不能表示仓库已覆盖；扫描尚无可恢复分片游标 |
| Pattern 与候选筛选 | 底层一次最多 256 个 Pattern；服务最多读取 1000 个注册版本；先保留最多 1000 个匹配，再抑制已有结论 | 超限需主动分片；大量被抑制的高分项可使后面的新机会得不到补位 |
| 字面与热点规则 | 删除行蒸馏只产出草稿；需要人工策展；热点必须对应扫描提交；同名文本不证明语义等价 | 未知适用性应继续进入工作台，不能靠提高分数消除不确定性 |
| SQLite WAL | 读辅助函数也进入 `BEGIN IMMEDIATE`；部分门禁事务内执行 Git；证据 JSON 与业务记录同库 | 并发写者串行，长 Git 操作可放大排队；当前没有数据库迁移版本链、外部对象存储和灾难恢复流程 |
| 状态一致性 | 候选转换、验证和晋升使用版本及幂等请求；其余写入口有不同控制方式 | 尚不能把“全部写操作具有同一外部幂等/审计契约”当成已实现保证 |
| 角色分离 | 服务比较调用者提供的 actor 字符串；本地 MCP 不开放责任人确认和策展晋升 | 工具分面有价值，但不同字符串不证明不同人，CLI/MCP 边界也不是认证系统 |
| OpenCode 交接 | 服务输出下一角色、版本、摘要、范围与证据；实际 worktree、进程和权限由执行器负责 | 交接包不等于任务已排队、已认领或已完成；旧 Markdown 工作流尚不能代替新服务状态 |
| A/B 验证 | 检查报告声明的设备、版本、镜像和策略一致性；使用逐对百分比的 Student-t 区间 | 不能证明硬件来源、镜像由某提交构建、样本独立、环境真实相同或采样没有选择偏差 |
| 知识召回和纠正 | 对所有技能记录做词项相关性排序并限制输出数量；目前仍全表扫描；纠正先记录关联和事件 | 尚无倒排索引；提出纠正不会自动使旧知识失效，也不会自动撤回已产生的交接 |

实现核对入口：[mining.py](C:/Users/irtos/ryan/workspace/hm-kernel-llm-opt/src/hmopt/evolution/mining.py)、[store.py](C:/Users/irtos/ryan/workspace/hm-kernel-llm-opt/src/hmopt/evolution/store.py)、[service.py](C:/Users/irtos/ryan/workspace/hm-kernel-llm-opt/src/hmopt/evolution/service.py)、[validation.py](C:/Users/irtos/ryan/workspace/hm-kernel-llm-opt/src/hmopt/evolution/validation.py)、[mcp.py](C:/Users/irtos/ryan/workspace/hm-kernel-llm-opt/src/hmopt/evolution/mcp.py)。

当前 `pipeline` 是带条件的候选分流标签，仍需责任人确认和评审。扫描覆盖被截断、历史启发式未策展等情况会保留在 `workbench`。报告中的 `hardware_verified` 应解释为“报告中硬件声明满足内部检查”，不能当成设备远程证明。

## 2. 通用平台边界与 scenario 契约

平台按“采集、定位、筛选、门禁、执行、验证、知识治理”划分。内存、吞吐、可靠性、安全回归等是可组合的场景配置，不能各自复制一套状态机或绕过共享门禁。

建议增加版本化 `ScenarioSpec`，组合以下适配接口；这些是待实现契约，而非当前已有类：

| 接口 | 输入与输出 | 平台统一约束 |
|---|---|---|
| `SourceAdapter` | 仓库/评审系统事件 → 提交、评审、回退及引用关系 | 源身份、不可变事件 ID、采集游标、访问范围、完整性状态 |
| `ContextAdapter` | revision、目标范围 → 代码/配置/运行证据及定位锚点 | 所有结果带来源和版本；文本与图关系区分语义事实和启发式 |
| `OpportunityAdapter` | 已激活 Pattern、上下文 → 可解释候选 | 返回命中条件、缺失前提、成本估计与证据，不产生隐式执行权限 |
| `ExecutorAdapter` | 已批准交接包 → 隔离执行、提交与产物清单 | 认领租约、权限限制、幂等键、取消协议和可审计进程结果 |
| `MeasurementAdapter` | 冻结实验计划 → 原始样本、环境、产物及采集证明 | 不能修改验收策略；区分模拟/硬件/其他可信执行环境 |
| `EvaluatorAdapter` | 指标类型、冻结规则与原始证据 → pass/fail/inconclusive | 算法版本、适用假设、误差控制、拒绝原因和可重放计算 |
| `KnowledgeAdapter` | 经验证结论或反例 → 候选知识与适用范围 | 先 journal，保留验证谱系，策展决定分发与失效 |

例如同一候选可以采用吞吐主指标、延迟护栏和功能断言，也可以采用缺陷触发率主指标、资源消耗护栏。不能把所有验证都转换为 instruction count，也不能把所有可靠性事件直接套进当前均值百分比区间。现有 `Plan.bottleneck` 分类可保留作描述字段，后续 scenario 标识和版本应独立扩展。

## 3. P2：把本地门禁接入可恢复的真实工作流

P2 先建立操作可靠性和可观测性，再扩大候选数。以下退出条件是建议验收标准，需要纳入测试与实际部署验收；不是当前测试结果。

### P2-01：统一身份、数据版本与写入契约

**交付物：** 仓库注册表与不可变 `repo_id`、来源 ID 映射、schema migration、候选尝试链、所有写 API 的幂等规范；身份认证与角色授权；读事务和写事务分离；短事务加 outbox；备份/恢复工具和演练记录。

仓库路径改为部署位置，不能继续承担跨主机的全局身份。需要给 `repo_id + ref_scope + source_adapter_version` 建立采集游标，显式处理改写、仓库移动和重复克隆。原有本地路径 ID 必须可迁移并保留别名，不能静默重建全部出处。

Git、模型、构建及采集等长操作放在数据库事务外。先读取状态版本，执行有界只读准备，再用版本检查提交；涉及外部执行时用 outbox 发出任务。不能用“放到事务外”代替提交时的 revision/摘要复核。

**依赖：** 当前 schema、证据摘要及门禁测试；明确部署身份提供者。

**退出条件：** 对请求重发、并发批准、写入前后崩溃、备份恢复进行故障注入；验收集中没有丢失的已确认转换、没有重复生效的请求、没有丢失出处的证据。所有有权限影响的写入口都明确 actor 来源、授权范围、expected_version 和 request_id 语义。

**度量：** 写锁等待 p95/p99、冲突与重试率、审计覆盖率、恢复点和恢复耗时、证据校验失败数。容量指标必须注明硬件、对象数、证据体积与并发读写比例。

### P2-02：可恢复历史与评审采集

**交付物：** Git/评审系统适配器、分片任务清单、事件去重、完整性元数据、回退/撤销关联、可恢复游标和死信处理。

保留第一父链作为一种明确的采集模式，另提供完整提交图/评审事件模式。后者不能只用一个“最后提交”代表多个并行分支的覆盖；需要事件游标或已处理图前沿，并记录目标 ref 的采集 epoch。截断补采应增加证据版本，不应把不完整旧记录悄悄替换成另一内容。

**依赖：** P2-01 的稳定源身份、迁移和写契约。

**退出条件：** 固定测试仓库覆盖分支合并、回退、强制改写、超大提交和跨页恢复；中途终止后重放，已声明覆盖范围内无遗漏、无重复有效源事件。分页响应分开报告“本页完成”“目标已追平”“部分内容待补采”。

**度量：** 源事件延迟、ref 覆盖率、缺失/截断比例、每千提交采集字节与耗时、死信年龄、成功补采率。没有明确定义总体的“采集了 N 条记录”不能充当覆盖率。

### P2-03：可分片机会筛选与公平预算

**交付物：** 固定 tree 的扫描 manifest、路径/Pattern 分片与断点、按 blob 内容缓存的廉价谓词结果、反例索引、候选补位、按团队配额的任务预算，以及少量语义验证插件。

把原有全库上限改为可观测分页边界。负面结论过滤应在全局 Top-N 前或支持持续补位，避免已处理高分项占满内部 Top-1000。不同 Pattern 和目录保留抽样名额，防止启发式高分长期垄断机会。语义检查只处理通过字面范围筛选的候选，记录实际 token、时间和失败成本。

复用旧 clangd/Neo4j 前，必须先解决 revision 命名空间、符号身份、嵌入兼容、缺失模块和截断内容等问题。旧图不能作为已经可信的语义事实直接进入自动决策。

**依赖：** P2-01、P2-02；带正确/错误标注的小型候选基准集。

**退出条件：** 小仓库的完整扫描与分页合并结果一致；固定候选预算下，重复执行结果可解释且稳定；被抑制高分项不能阻止后续合格新项返回；取消/恢复不漏掉 manifest 中的分片；没有用不完整覆盖报告“已完成全库筛选”。

**度量：** 文件和 Pattern 覆盖率、每有效候选成本、缓存命中率、Top-K 精度、语义阶段淘汰率、各团队候选配额使用率。命中数量不能代替责任人确认率。

### P2-04：OpenCode 执行桥与责任人工作台

**交付物：** manager 交接适配器、任务注册表、worktree 管理器、worker 认领租约、取消/恢复操作、角色与路径权限、责任人确认工作台、状态投影视图。

桥接流程应为：

1. OpenCode manager 读取新服务的候选状态和版本，领取与当前阶段对应的交接包。
2. 人类身份完成责任人确认；策展和晋升由独立授权角色执行。更换 actor 字符串不能改变权限。
3. 方案批准后，执行器从批准的 commit 创建隔离 worktree，将 plan digest、允许路径及运行权限写入任务记录。
4. 实施者只返回不可变提交和产物引用，服务重新计算差异并验证范围；评审绑定该差异的摘要。
5. 验证 worker 只消费 code-approved 任务。Markdown、OpenCode 消息与旧 MCP 状态均只是视图或外部证据，不能推进权威状态。
6. 完成、失败、超时和取消都回传结构化事件；失联恢复先查询已有任务和产物，不能盲目重放烧写等操作。

队列使用“至少一次交付 + 幂等处理 + 租约代数令牌”。设备、worktree 和构建资源按需独占。已过期 worker 的结果或副作用请求必须被资源端拒绝；仅在调度器中检查租约不够。

**依赖：** P2-01；现有 `.opencode` 角色和 Build/Flash/Auto-Test 工具的契约核对；可隔离的执行资源。

**退出条件：** 在双 worker 竞争、失联、重启和重复回调测试中，不发生同一资源的并发有效认领；陈旧 state_version、plan digest 和租约均被拒绝；独立评审身份得到认证；未经授权不能确认、实施或调用设备操作。影子执行通过后，才进入明确授权的小范围真实执行。

**度量：** 认领冲突、租约过期、重复回调、取消延迟、孤立 worktree/任务数、责任人队列长度、每个确认候选的人工处理时间。

### P2-05：可信采集与通用实验协议

**交付物：** 构建产物证明、采集器签名报告、原始样本存储、设备/环境租约、冻结实验 manifest、度量适配器与可重放评估器。

签名对象应覆盖 source revision、构建配置/工具链、实际镜像摘要、设备/执行环境、工作负载摘要、采集器版本、配对关系、顺序与原始数据摘要。签名只证明受信任身份签过这些字节；还需要设备端测量和构建链验证，才能把实际运行镜像绑定到批准提交。

实验计划预先规定采样单元、配对与随机顺序、预热、冷却、排除规则、样本量或合法追加采样策略。当前 `retry_validation` 允许不确定测量重试；生产协议不能把无限次重试直到显著当成有效证据。不同指标类型选择相应统计方法，并保留旧评估器版本用于复现。

**依赖：** P2-01、P2-04；可访问的真实构建/运行资源与可信采集器。

**退出条件：** 模拟标志、签名失效、重放报告、镜像/提交不匹配、未批准策略变化均不能进入真实验收；原始样本重算与保存结论一致；成功和失败均可追溯到同一实验 manifest。至少完成一个明确授权场景的真实闭环，发布实际原始证据和限制，而不把临时模拟数据计入真实通过率。

**度量：** 完整证明链比例、有效实验率、环境失配率、不确定率、测量重试成本、策略违例数、真实验收后回归率。

### P2-06：运行面板与容量基线

**交付物：** 以事件生成的漏斗面板、团队预算、异常告警、作业和证据保留策略、容量压测脚本、可复现压测报告。

在约定硬件上分别扩展提交数、文件数、Pattern 版本数、并行仓库数和证据体积，不能只用单次 demo 耗时推断规模。先测 SQLite 读写竞争和全文召回成本，再决定是否需要 PostgreSQL、对象存储和专门检索系统；更换存储不能替代语义与幂等契约。

**依赖：** P2-01 至 P2-05 的事件、预算和实验标识。

**退出条件：** 压测报告明确负载、硬件、失败率及 p50/p95/p99；超预算能暂停新工作且不丢弃已确认状态；监控区分队列完成、进程成功、有效测量和收益通过；所有核心漏斗指标可以从可核验事件重算。

**度量：** 每阶段排队/服务时间、吞吐、错误率、存储增长、每有效候选成本、每真实通过实验成本，以及跨团队资源公平性。

| P3-03 Pattern 生命周期 | 合并/拆分/退役/迁移、版本依赖、反例范围、到期复核、变更影响清单 | P2 稳定身份与候选谱系 | 退役/纠正能识别受影响候选与交接；未执行任务自动暂停待复核；已执行修改进入显式回归处置，不自动改写历史 | 过期命中率、受影响任务识别率、反例迁移正确率 |
| P3-04 Hub 治理与分发 | journal/staging/hub 的访问和发布策略、评测 CI、签名包、撤回/替代关系、订阅同步 | P3-01/03、P2-05 证明链 | 纠正经策展生效后默认召回不再给出被替代版本；升级和降级可复现；不同路径或镜像哈希不能单独充当独立复现证明 | 跨上下文真实复现率、过期知识召回率、撤回传播延迟 |
| P3-05 选择性连续调度 | 经过授权的 scenario 自动认领范围、风险分层、资源配额、熔断、分批发布/回退交接 | P2 全部；P3-01 至 P3-04 质量基线 | 先影子运行，再小范围试点；每个自动任务仍通过确认与评审授权契约；故障演练能停发新任务并恢复已确认状态 | 净收益、回退率、生产异常关联率、自动化覆盖与人工负担 |

P3 的“学习”优先指提高模式、证据和选择策略的质量。模型更新、技能自动优化和新执行权限必须独立评审。验证成功不能自动授权修改更大的文件范围，知识召回也不能替代当前 revision 的适用性检查。

## 5. 必须同时推进的实验与知识约束

当前 A/B 以逐对百分比等权计算，且主指标区间需要达到批准阈值。它仍依赖样本独立、代表性和近似适当的分布假设；不能识别温控漂移、相关重复、选择性上报或伪造来源。护栏以允许的平均回退判定，也不等价于每条尾延迟或每个场景都无回退。

当同时筛选许多候选、许多指标、或不断重试实验时，应在实验协议中明确多重比较、追加采样和确认集规则。结论必须包含适用范围，不能把一次工作负载的收益扩写为全平台收益。可靠性计数、稀有错误率等场景应使用匹配该采样过程的评估适配器。

知识晋升的复现应显式描述独立维度，例如另一个目标系统、另一个工作负载配置、独立构建与采集链。当前不同 `source_context` 和镜像对是基础检查，不证明这些独立性。否决原因也应区分语义不适用、测量无效、资源不足、已解决和实证回退；不同原因需要不同的抑制期限与解除流程。

## 6. 验收顺序与指标口径

建议按 `P2-01 → P2-02/03 → P2-04/05 → P2-06 → P3` 推进。前置数据与身份契约未完成时，可以并行开发适配器，但不能宣布生产闭环已经建立。

统一统计口径：

- **候选有效率：** 经独立标注确实适用的候选 / 完成独立标注的候选，同时报告未标注比例。
- **责任人确认率：** 已确认候选 / 已作出责任人决定的候选，同时报告仍待决定数量与年龄。
- **真实验证通过率：** 满足可信来源和冻结策略的通过实验 / 满足测量有效性要求的真实实验；模拟和无效报告单独统计。
- **复现率：** 在预先指定独立上下文通过的配方 / 已进入复现测试的配方，不能用知识条目数量替代。
- **回退率：** 已验证并实际部署后回退的修改 / 已实际部署且完成观察窗口的修改；尚未完成观察的修改单列。
- **成本：** 分开报告采集字节、CPU/模型消耗、构建/设备占用和人工时间，再按实际有效候选或真实通过实验归一化。

各阶段阈值应由团队在基线测量后批准，并冻结到验收配置中。未经验证的候选数量、代码生成行数、模拟通过率或单个漂亮案例，都不足以证明平台持续优化能力。
