# SkillHub：一种内核优化 Agent 的团队级经验治理与自进化技术

## 一、场景与问题

大模型驱动的内核优化（内存底噪、指令数、功耗）在团队里规模化铺开之后，瓶颈已经不是单次能不能优化出来，而是经验能不能积累下来。一次完整的优化会沉淀大量有价值的经验：哪个优化手法在哪类函数上有效、哪些方向试过了是死路、某个热点函数有什么修改禁忌、哪种验证方法在什么场景下不可信。这些经验目前只存在于每个工程师自己的工作目录里，团队层面拿不到：人一走经验就丢，新人和新部署的 Agent 每次都从零摸索，同一个方向被不同的人反复探索，同一个坑被反复踩。投入的人越多，重复浪费越明显，优化的边际效率不升反降。

举个真实例子：某次优化在 shrink_node 里把循环内重复读取的变量提出来，实测指令数降了 0.8%。这条经验对所有做内存回收优化的人都有用，但它只躺在一个人的本地目录里，别人既不知道它存在，更不会在研究同类函数时自动用上它。

## 二、为什么"直接共享"行不通

把大家的经验直接堆进一个共享库，会引入两个更隐蔽的问题。

一是知识会变质。内核版本在演进，去年正确的结论今年可能已经失效；不同人对同一个函数也可能得出相反的结论。没有管理机制的共享库，积累越多、自相矛盾越多，最后没人敢信。

二是 AI 自我积累会越滚越偏。让 Agent 自己总结经验、自己消费经验，容易形成"反馈自增强"：平均指标看着在变好，个别场景被悄悄做坏，而且很难发现是哪条经验带偏的。

业界的 Agent 记忆方案（mem0、Zep、memU 等）解决的都是单个 Agent"怎么存、怎么取"，矛盾治理、质量把关、团队级复用都没有解决。简单用 git 共享文档也不行：按行合并处理不了"两条经验语义上矛盾"这种问题，技能文档还可能被某个人一周的坏经验直接覆盖掉。

## 三、方案描述

本课题设计实现 SkillHub：一个带质量门槛、带版本号的团队中央经验仓，把"消费、提炼、审核、发布、再消费"打通成一个自动闭环，让团队优化经验像内部软件包一样被管理：可积累、可验证、可追溯、越用越准。

**1. 经验分成两类，分开管理（最重要的设计）。** 知识（事实、教训、失败案例）和技能（做法、流程）性质完全不同，必须用两套办法：

- 知识库只增不删。新经验入库前先和已有记录做七种关系判定：重复的合并出处、矛盾的按证据强弱取舍、过时的标记失效、适用条件不同的共存、一条是另一条推广的建立关联等。被取代的旧记录不删除，标记"已被取代"并记录生效时间段，历史随时可查、来源随时可追——这是防止知识变质的根本手段。
- 技能库靠竞争进化。技能文档被当作可以持续优化的"参数"：任何修改必须在固定评测集上总分不降、单项零退化才允许合入，达不到就拒绝。多人同时改进同一个技能时不强行合成一个版本，各有所长的候选都保留，避免互相覆盖。我们正在把 GEPA（一个自动反思改写、多候选择优的进化框架）集成进这个环节，让技能文本的优化和发布验证自动跑起来。

**2. 全流程自动化，研发习惯零改动。** 工程师照常干活：优化任务开始时，系统按当前函数自动检索中央仓，把相关的团队经验注入 Agent 的上下文；任务收口时自动从本地产物里提炼候选经验——先用固定规则提取结构化指标，再用大模型补充提取规则覆盖不到的心得——生成统一格式的记录；候选先过 CI 的五道自动检查（格式校验、敏感信息扫描、去重、评测把关等），再由两名评审（一名看领域内容、一名看流程规范）人工把关后入库；每晚的定时任务做归并、优化和发布。发布带版本号，各项目锁定自己使用的版本，出新版后自动通知升级，出问题一键回退。整个链路通过 MCP 接口接进现有优化流水线，中央仓故障时自动跳过、绝不阻塞正常工作。

**3. 晋升有门槛，防止不可靠的经验混进核心资产。** 一条知识要升级为团队级技能，必须在至少两个不同函数上被独立验证有效；技能要进入核心库，需要两名负责人签字。系统只负责发现和提名候选，要不要晋升始终由人拍板。

## 四、当前进展

双仓全链路已经实现并可离线复现：154 项测试、5 道 CI 检查、3 个 MCP 接口全部就绪；检索评测 26 条查询全部命中，关系判定基准 48 例全对，技能评测门演示从 0.67 提到 1.00。GEPA 集成进行中，真机收益数据随试点回填。

## 五、预期收益与应用场景

- 新人和新部署的 Agent 第一天就带着全队经验干活，重复探索和重复踩坑预期减少一半以上，冷启动从周级缩短到天级；
- 专家经验沉淀为有质量把关的团队资产，不再随人员流动流失；
- 优化命中率和吞吐随使用持续提升，经验第一次成为可以复利的资产，而不是一次性消耗品；
- 方案不绑定内核优化：内存底噪、指令数、功耗、编译器后端等任何 Agent 驱动的代码与性能优化场景都可以直接复用这套经验仓。它同时也是对 self-evolving agent 长期记忆这一研究热点的工程化回答：经验能安全积累、矛盾能被管理、全过程可审计。
